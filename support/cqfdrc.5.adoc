== NAME

cqfdrc - project information config file

== DESCRIPTION

The _.cqfdrc_ file at the root of your project contains the information
required to support project tooling. It is written in an .ini-like format.

=== COMMENTS

The _.cqfdrc_ file supports Unix shell comments; the words after the character
_#_ are ignored up to the end of line. A comment cannot be set in the first
line, and right after a section.

=== THE PROJECT SECTION

*org*::
	A short, lowercase name for the project’s parent organization.

*name*::
	A short, lowercase name for the project.

*flavors (optional)*::
	The list of build flavors (see below). Each flavor has its own command
	just like _build.command_. _flavors_ is *deprecated*; flavors are now
	automatically deduced from the flavor sections of _.cqfdrc_.

*build_context (optional)*::
	_build_context_ is *unsupported*.

*custom_img_name (optional)*::
	_custom_img_name_ is *unsupported*.

*tag (optional)*::
	_tag_ is *unsupported*.

*image (optional)*::
	_image_ is *unsupported*.

=== THE BUILD SECTION

==== CQFD RUN

*command*::
	The command string to be executed when _cqfd_ is invoked. This string
	will be passed as an argument to a classical _sh -c "commands"_, within
	the build container, to generate the build artefacts.

*distro (optional)*::
	The name of the directory containing the Dockerfile. By default, _cqfd_
	uses _"docker"_, and _.cqfd/docker/Dockerfile_ is used.

*user_extra_groups (optional)*::
	_user_extra_groups_ is *unsupported*.

*shell (optional)*::
	The program used to invoke the _shell_ command.

*path (optional)*::
	Set the _PATH_ environment variable in the build container.

*platform (optional)*::
	Set the desired target platform.

*docker (optional)*::
	The program used to invoke the _docker(1)_ client.

*dockerfile (optional)*::
	The path to the _Dockerfile_. The path is relative to the project
	directory (i.e. the parent directory of _.cqfd_). By default, _cqfd_
	uses _.cqfd/$distro/Dockerfile_ with _distro=docker_ if _distro_ is
	unset.

*docker_build_args (optional)*::
	A space-separated list of extra arguments used to invoke _docker
	build_.

*docker_pull_args (optional)*::
	A space-separated list of extra arguments used to invoke _docker
	pull_.
	_docker_pull_args_ is *unsupported*.

*docker_run_args (optional)*::
	A space-separated list of extra arguments used to invoke _docker run_.

*docker_rmi_args (optional)*::
	A space-separated list of extra arguments used to invoke _docker rmi_.

*bind_docker_sock (optional)*::
	Set to `true` to enable forwarding the docker socket to the container.

==== CQFD RELEASE

*files*::
	The space-separated list of files generated by the build process to
	include inside a standard release archive.

*archive (optional)*::
	The name of the release archive generated by _cqfd_. You can include
	environment variable names, as well as the following template marks:
	* *%Gh* - git short hash of the last commit
	* *%GH* - git long hash of the last commit
	* *%D3* - RFC3339 date (YYYY-MM-DD)
	* *%Du* - Unix timestamp
	* *%Cf* - current cqfd flavor name (if any)
	* *%Po* - value of the _project.org_ configuration key
	* *%Pn* - value of the _project.name_ configuration key
	* *%%* - a literal _%_ sign

By default, _cqfd_ will generate a release archive named _org-name.tar.xz_,
where _org_ and _name_ come from the project's configuration keys. The .tar.xz,
.tar.gz and .zip archive formats are supported.

For tar archives:

* (Optional) Setting _tar_transform=yes_ or _tar_transform=true_ will cause all
  files specified for the archive to be stored at the root of the archive,
  which is desirable in some scenarios.

* (Optional) Setting _tar_options_ will pass extra options to the tar
  command. For example, setting _tar_options=-h_ will archive the files that
  symlinks point to instead of the symlinks themselves, which is desirable in
  some scenarios.
